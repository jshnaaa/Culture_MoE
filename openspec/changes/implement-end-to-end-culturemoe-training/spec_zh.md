# 端到端CultureMoE训练技术规范

## 新增需求

### 需求: 联合参数优化
系统必须支持基础语言模型和MoE组件的同时训练，无参数冻结。

#### 场景: 初始化端到端训练
- **给定** 预训练基础模型 (LLaMA-3.1-8B-Instruct 或 Qwen-2.5-7B-Instruct)
- **且** 现有的微调LoRA权重
- **且** MoE架构配置 (专家数量，隐藏维度)
- **当** 为端到端训练初始化CultureMoE模型时
- **那么** LoRA权重必须被加载并合并到基础模型中
- **且** 所有模型参数 (包括合并的LoRA) 必须可训练 (无冻结层)
- **且** MoE组件必须用适当的随机权重初始化
- **且** 微调模型参数必须保留其学习到的值

#### 场景: 配置分层学习率
- **给定** 包含微调模型和MoE组件的CultureMoE模型
- **当** 为端到端训练设置优化器时
- **那么** 微调模型参数必须使用较低学习率 (1e-6 到 5e-6)
- **且** MoE路由器参数必须使用中等学习率 (1e-5 到 5e-5)
- **且** 专家网络参数必须使用较高学习率 (1e-4 到 5e-4)
- **且** 共享专家参数必须使用中等学习率 (1e-5 到 5e-5)

### 需求: 内存高效联合训练
系统必须通过优化技术处理联合训练期间的内存约束。

#### 场景: 应用混合精度训练
- **给定** 准备进行端到端训练的CultureMoE模型
- **当** 配置训练精度时
- **那么** 微调模型层必须使用bfloat16精度
- **且** MoE组件必须使用float32精度以保持稳定性
- **且** 梯度缩放必须适当地应用于混合精度

#### 场景: 实现梯度累积
- **给定** 联合训练期间的内存约束
- **当** 使用有限GPU内存进行训练时
- **那么** 梯度累积步数必须可配置 (默认4-8)
- **且** 有效批量大小必须等于 批量大小 × 累积步数
- **且** 梯度必须按累积步数正确归一化

#### 场景: 启用梯度检查点
- **给定** 微调模型层消耗大量内存
- **当** 内存使用超过可用GPU内存时
- **那么** 必须为微调模型层启用梯度检查点
- **且** 内存使用必须以计算时间为代价减少
- **且** 梯度计算必须保持数学正确性

### 需求: 训练稳定性管理
系统必须确保联合优化期间的稳定收敛。

#### 场景: 实现文化损失预热
- **给定** 带有文化损失组件的联合训练设置
- **当** 从第1轮开始训练时
- **那么** 第1-5轮必须仅使用语言建模损失 (预热因子 = 0.0)
- **且** 第6-10轮必须逐渐增加文化损失权重 (预热因子 = 0.0 到 1.0)
- **且** 第11轮及以后必须使用完整文化损失权重 (预热因子 = 1.0)
- **且** 总损失必须为: 语言损失 + 预热因子 × 文化损失权重 × 文化损失

#### 场景: 应用梯度裁剪
- **给定** 可能存在梯度不稳定的联合训练
- **当** 计算参数更新的梯度时
- **那么** 梯度范数必须裁剪到最大值1.0
- **且** 裁剪必须应用于所有参数组
- **且** 梯度裁剪必须防止训练发散

#### 场景: 调度路由器温度
- **给定** 容易发生专家崩塌的MoE路由器
- **当** 训练在各轮次中进展时
- **那么** 路由器温度必须在早期轮次从5.0开始
- **且** 温度必须在训练过程中逐渐降低到2.0
- **且** 温度调度必须防止专家崩塌

### 需求: 全面训练监控
系统必须提供联合训练进展的详细监控。

#### 场景: 跟踪组件特定指标
- **给定** 带有多个参数组的端到端训练
- **当** 监控训练进展时
- **那么** 必须分别跟踪基础模型和MoE组件的梯度范数
- **且** 必须记录每个参数组的学习率
- **且** 必须单独跟踪损失组件 (语言、文化、专门化、多样性)
- **且** 必须监控路由器权重分布以检测崩塌

#### 场景: 检测训练不稳定性
- **给定** 易受数值问题影响的联合训练
- **当** 处理每个训练批次时
- **那么** 必须立即检测NaN或无限损失
- **且** 必须跳过有问题的批次并记录日志
- **且** 必须通过梯度范数检测梯度爆炸
- **且** 训练必须在不稳定事件后优雅地继续

### 需求: 配置和向后兼容性
系统必须支持灵活配置同时保持兼容性。

#### 场景: 配置端到端训练参数
- **给定** 端到端方法的训练配置
- **当** 解析命令行参数或配置文件时
- **那么** 端到端模式必须可通过 `--training_mode end_to_end` 选择
- **且** 分层学习率必须可按组件类型配置
- **且** 预热调度参数必须可配置
- **且** 内存优化设置必须可配置

#### 场景: 保持向后兼容性
- **给定** 现有的两阶段训练工作流
- **当** 使用更新的训练系统时
- **那么** 两阶段训练模式必须通过 `--training_mode two_stage` 保持可用
- **且** 现有配置文件必须继续工作
- **且** 现有shell脚本必须无需修改即可运行
- **且** 模型输出格式必须保持兼容

## 修改需求

### 需求: 模型参数管理
系统必须更新参数管理以支持联合训练而不是选择性冻结。

#### 场景: 初始化可训练参数
- **给定** 用于训练的CultureMoE模型
- **当** 设置参数优化时
- **那么** 默认情况下所有模型参数必须可训练
- **且** 必须根据组件类型创建参数组
- **且** 除非明确配置，否则不得冻结参数
- **且** 参数计数必须反映所有可训练参数

### 需求: 训练循环集成
系统必须修改训练循环以处理联合优化需求。

#### 场景: 执行联合训练步骤
- **给定** 训练批次和联合优化设置
- **当** 执行训练步骤时
- **那么** 前向传播必须计算所有损失组件
- **且** 反向传播必须为所有参数组计算梯度
- **且** 优化器步骤必须使用各自学习率更新所有参数组
- **且** 梯度累积必须在所有参数组中正确工作

## 移除需求

### 需求: 选择性参数冻结
移除阻止联合优化的参数冻结机制。

#### 场景: 消除参数冻结
- **给定** 准备训练的CultureMoE模型
- **当** 设置训练配置时
- **那么** 必须禁用微调模型参数冻结
- **且** 必须移除选择性参数解冻逻辑
- **且** 所有参数必须参与梯度计算

#### 场景: 移除可训练参数限制
- **给定** LoRA权重加载和合并过程
- **当** 从预训练权重创建PeftModel时
- **那么** 必须移除 `is_trainable=False` 参数
- **且** 合并的LoRA权重必须保持可训练
- **且** 不得施加人为参数限制
