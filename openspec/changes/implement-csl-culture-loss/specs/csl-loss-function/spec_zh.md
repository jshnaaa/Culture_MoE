# CSL文化损失函数规范

## 新增要求

### 要求：CSL损失函数实现
当指定`USE_CULTURE_LOSS=csl`时，系统应实现文化相似性损失（CSL）函数，计算三个互补的损失组件。

#### 场景：CSL损失计算
**给定** 具有文化标签和专家输出的样本批次
**当** 配置`USE_CULTURE_LOSS=csl`时
**则** 系统应计算`L_culture = L_culture_router + L_culture_share + L_culture_sr`
**且** 每个组件应为模型优化贡献有意义的梯度

#### 场景：路由专家文化相似性损失
**给定** 批次中所有样本的路由专家权重向量`wr_i`
**当** 计算`L_culture_router`时
**则** 对于所有样本对(i,j)，其中i < j：
- **如果** `cul_i == cul_j` **则** 添加`(1 - sim(wr_i, wr_j))`以鼓励相似性
- **如果** `cul_i != cul_j` **则** 添加`sim(wr_i, wr_j)`以惩罚相似性
**且** 最终损失应对所有对求平均

#### 场景：共享专家文化无关损失
**给定** 批次中所有样本的共享专家输出向量`es_i`
**当** 计算`L_culture_share`时
**则** 对于所有样本对(i,j)，其中i < j：
- 不考虑文化标签，添加`(1 - sim(es_i, es_j))`
**且** 最终损失应对所有对求平均
**且** 这应强制共享专家学习文化无关表示

#### 场景：共享-路由解耦损失
**给定** 所有样本的共享专家输出`es_i`和路由专家输出`er_i`
**当** 计算`L_culture_sr`时
**则** 对于所有样本i：
- 添加`sim(es_i, er_i)`以惩罚相似性
**且** 最终损失应对批次求平均
**且** 这应鼓励共享和路由专家之间的互补表示

### 要求：余弦相似度实现
系统应实现余弦相似度为`sim(x, y) = (x · y) / (||x|| * ||y||)`，具有适当的数值稳定性。

#### 场景：数值稳定性
**给定** 两个向量x和y
**当** 计算余弦相似度时
**则** 系统应检查零向量（范数 < 1e-8）
**且** 应为零向量情况返回零相似度
**且** 应优雅地处理NaN和Inf值

#### 场景：批量向量化
**给定** 需要相似性计算的大批次
**当** 计算成对相似性时
**则** 系统应尽可能使用向量化操作
**且** 应高效管理内存以避免OOM错误
**且** 应为所有相似性计算保持梯度流

### 要求：专家输出提取
系统应从JointLoRAMoEModel提取CSL计算所需的专家输出。

#### 场景：路由专家输出提取
**给定** JointLoRAMoEModel前向传播的模型输出
**当** 需要CSL损失计算时
**则** 系统应提取路由专家融合输出`er_i`
**且** 应验证张量形状和类型
**且** 应处理路由输出不可用的情况

#### 场景：共享专家输出提取
**给定** JointLoRAMoEModel前向传播的模型输出
**当** 需要CSL损失计算时
**则** 系统应提取共享专家输出`es_i`
**且** 应验证张量形状和类型
**且** 应处理未配置共享专家的情况

#### 场景：路由权重提取
**给定** JointLoRAMoEModel前向传播的模型输出
**当** 需要CSL损失计算时
**则** 系统应从softmax输出提取路由权重向量`wr_i`
**且** 应确保权重是K维向量
**且** 应验证权重归一化属性

### 要求：训练流水线集成
当配置时，系统应将CSL损失集成到联合训练流水线中。

#### 场景：CSL激活
**给定** 训练配置为`USE_CULTURE_LOSS=csl`
**当** 执行训练轮次时
**则** 系统应使用CSL损失而不是现有文化损失
**且** 应保持与其他损失模式的向后兼容性
**且** 应保持所有现有训练功能

#### 场景：损失组件日志记录
**给定** 训练期间的CSL损失计算
**当** 记录训练指标时
**则** 系统应记录各个CSL损失组件
- `L_culture_router`值
- `L_culture_share`值
- `L_culture_sr`值
- 总`L_culture`值
**且** 应在训练进度显示中包含CSL组件

#### 场景：配置验证
**给定** 训练脚本执行
**当** 指定`USE_CULTURE_LOSS=csl`时
**则** 系统应验证模型提供所需的专家输出
**且** 应验证文化标签可用
**且** 应为配置问题提供清晰的错误消息

### 要求：性能优化
系统应高效实现CSL损失计算以最小化训练开销。

#### 场景：计算开销
**给定** 训练期间的CSL损失计算
**当** 测量训练性能时
**则** CSL开销应小于总训练时间的10%
**且** 应随批次大小增加合理扩展
**且** 应在可接受范围内保持训练吞吐量

#### 场景：内存管理
**给定** 大批次和长序列
**当** 计算CSL损失时
**则** 系统应高效管理内存
**且** 应避免存储不必要的中间张量
**且** 应优雅地处理内存约束

#### 场景：梯度流保持
**给定** CSL损失组件
**当** 执行反向传播时
**则** 系统应通过所有相似性计算保持梯度流
**且** 应确保所有三个损失组件贡献有意义的梯度
**且** 应在优化期间保持梯度稳定性

## 修改要求

### 要求：文化损失配置
系统应支持`csl`作为`USE_CULTURE_LOSS`参数的新选项。

#### 场景：默认配置更新
**给定** `run_joint_lora_moe_training.sh`脚本
**当** 未指定`USE_CULTURE_LOSS`参数时
**则** 系统应默认为`USE_CULTURE_LOSS=csl`
**且** 应保持对现有选项（`ori`、`new`、`kl`、`false`）的支持

#### 场景：配置验证
**给定** 训练脚本执行
**当** 提供`USE_CULTURE_LOSS`参数时
**则** 系统应验证参数值
**且** 应接受`csl`作为有效选项
**且** 应为无效选项提供清晰的错误消息

### 要求：总损失计算
系统应保持现有的总损失公式，同时使用CSL作为文化组件。

#### 场景：损失公式保持
**给定** CSL文化损失实现
**当** 计算总训练损失时
**则** 系统应保持`L_total = L_generation + λ × (α × L_aux + β × L_culture)`
**且** 当`USE_CULTURE_LOSS=csl`时应使用CSL结果作为`L_culture`
**且** 应保持现有的损失权重机制
